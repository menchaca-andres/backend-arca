Objetivo

Centralizar la gestión de personal, vacaciones, contratos y boletas de ARCA en una plataforma modular, con responsabilidades separadas por servicio y datos aislados por schema.

Principios

  • Un bounded context por microservicio.
  • Un schema de PostgreSQL por servicio, sin FK entre schemas.
  • Comunicación interna por REST con X-Internal-Key.
  • TypeORM solo en repositorios y migraciones versionadas.

Estado actual

Sprint 1 con autenticación, catálogos de áreas y cargos, base del frontend e infraestructura. Los módulos de vacaciones, contratos y boletas están diseñados y tienen modelo de datos, pero sus endpoints aún no están implementados.

Vista general

Arquitectura C4

ADR-001 a ADR-007

El sistema se organiza en un frontend SPA, un API Gateway y cinco microservicios. Cada servicio es dueño de un schema de PostgreSQL y se comunica con los demás por contratos internos. Gotenberg convierte HTML a PDF para contratos y boletas.

Capas por servicio

route → controller → service → repository. Los controllers traducen HTTP; los services concentran reglas de negocio; los repositories son el único punto con TypeORM.

Seguridad

El gateway valida el JWT, descarta cabeceras de identidad enviadas por el cliente y propaga x-user-id, x-user-rol y x-funcionario-id. Las rutas /internal/* no salen por el gateway.

Persistencia

Una instancia PostgreSQL con seis schemas: autenticacion, personal, vacaciones, contratos, boletas y auditoria. Sin foreign keys entre schemas.

Contenedores y dependencias

Microservicios

6 schemas · 20 tablas

El gateway es el único punto de entrada público. Los servicios se llaman entre sí por /internal/* con timeout de 3 segundos y un reintento. Los PDFs viven en tablas separadas con columna bytea.

Dependencias permitidas

Vacaciones, contratos y boletas consultan a personal. Personal y auth se llaman en ambos sentidos solo para baja y validación de funcionario. No hay ciclos en tiempo de ejecución.

Resiliencia

Cliente HTTP común con timeout de 3 segundos, un reintento y respuesta 503 cuando el servicio de destino no está disponible. Los errores usan { code, message, details }.

Documentos

Gotenberg convierte HTML a PDF. El archivo se guarda en una tabla separada y el hash SHA-256 vive en la fila padre para verificar la descarga.
